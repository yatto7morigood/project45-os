# 安全な実データ取得レイヤー設計（v1.1）

## 判定

`public_fetch` は **非推奨** とする。2026-08-28 時点のジモティー利用規約は、投稿等を「クロール等で自動的に収集、解析する行為」を禁止している。公開 HTML であっても、定期取得・解析を実装しない。CAPTCHA、ログイン、robots、レート制限、その他のアクセス制御を回避する処理は作らない。

## 優先する入力経路

1. ユーザーが取得した CSV/JSON を `manual_import` に投入する。
2. 許可された通知メールをユーザーがエクスポートし、専用のメール-to-JSON 変換（ローカル処理・本文最小化）で投入する。
3. ユーザーが検索結果または公開通知から必要フィールドを確認し、CSV/JSON に転記する。
4. 将来、ジモティーが明示的に許諾する API / RSS / データ提供契約が利用できる場合のみ、その仕様・認証範囲・頻度・保存範囲に従う専用 provider を追加する。

## provider の契約

各 provider は `list[dict]` を返すだけとし、`source_kind`、取得日時、原情報 URL、利用許諾根拠を記録する。許諾確認が失効・不明・エラーの場合は空配列とデータ未取得のレポートを返し、リトライで回避しない。重複・価格変更は SQLite で判定する。

## 日次運用

scheduled workflow は外部取得をしない。入力がなければ候補 0 件のレポートを生成して正常終了する。fixture は pytest と明示的な手動デモだけに限定する。型番・状態が未確定でも、入力された根拠から価値が見込める場合は `inferred_opportunity` に残し、確認事項を表示する。
